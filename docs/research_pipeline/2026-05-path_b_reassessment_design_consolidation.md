## 3. Consolidation method

This consolidation consumes only options A-F from WP-S2c-121. It does not add
new options and does not materially change option intent.

The wording below rephrases the options into later Main/Karl resolution wording.
Each option has:

- proposed lock-candidate wording;
- preservation note;
- if-locked downstream implication;
- stop conditions / modification triggers;
- resolution field for LOCK / MODIFY / DEFER / REJECT.

Any later locking package requires explicit Main/Karl resolution after this
document is surfaced in chat.

## 4. Consolidated option surface

The proposed lock-candidate surface is:

- Option A - hold / no Path B execution.
- Option B - narrow Path B within current taxonomy and timeframe discipline.
- Option C - information-input combination expansion within locked taxonomy.
- Option D - candidate-instance dimension expansion.
- Option E - broader evidence-kind expansion bounded by current locks.
- Option F - mixed phased Path B.

All are proposed lock candidates only. Locking one or more options would still
not by itself authorize execution unless the later Main/Karl resolution
explicitly authorizes an execution-authorization package or execution route.

## 5. Option A lock-candidate - hold / no Path B execution

- Status: PROPOSED / NOT LOCKED / NOT SELECTED / NOT AUTHORIZED.
- Proposed lock-candidate wording:
  - Path B execution remains deferred for now. The project maintains current
    infrastructure and waits for later Main/Karl routing or new evidence before
    authorizing any Path B execution.
  - No evidence-kind expansion is authorized.
  - No candidate registration, hypothesis pre-registration, backtest, research
    artifact, or execution tranche is created.
  - Future routing may revisit Path B after state refresh, but this option
    itself creates no execution work.
- Preservation note: all gates, locks, human gates, Phase 1 paper runtime
  protection, Tier 4 boundaries, and Path B non-authorization remain unchanged.
- If locked, likely downstream shape: downstream Path B execution cost remains
  zero WPs unless later Main/Karl reopens the route.
- Modification / defer / reject triggers:
  - Modify if Main/Karl wants a scheduled refresh checkpoint.
  - Defer if Main/Karl wants to wait for other route decisions first.
  - Reject if Main/Karl wants an active re-prime route now.
- Decision needed: LOCK / MODIFY / DEFER / REJECT.

## 6. Option B lock-candidate - narrow Path B within current taxonomy and timeframe discipline

- Status: PROPOSED / NOT LOCKED / NOT SELECTED / NOT AUTHORIZED.
- Proposed lock-candidate wording:
  - Path B may be prepared as a narrow current-taxonomy/current-timeframe
    discipline route that examines under-covered strategy-family, timeframe,
    and information-input combinations already permitted by repo truth.
  - The route must not add information-input taxonomy labels, modify
    timeframe-status discipline, contact Tier 4/protected paths, register
    candidates, pre-register hypotheses, run backtests, or create artifacts
    unless a later execution-authorization package explicitly permits those
    actions.
  - Any later execution design must preserve D2-006, D2-007, REC-5, permanent
    human gates, WP-S2c-100 locked criteria, and Path B execution
    non-authorization until separately resolved.
- Preservation note: D2-006, D2-007, REC-5, permanent human gates, locked
  taxonomy/timeframe discipline, and Phase 1 paper runtime protection remain
  unchanged.
- If locked, likely downstream shape: a small locking/authorization package plus
  a limited execution tranche only if later authorized; rough cost remains low
  single-digit to low-teens WPs.
- Modification / defer / reject triggers:
  - Modify if exact allowed evidence dimensions need tighter wording.
  - Defer if taxonomy/timeframe source confirmation is needed first.
  - Reject if Main/Karl decide narrow expansion cannot address the current
    pipeline gap.
- Decision needed: LOCK / MODIFY / DEFER / REJECT.

## 7. Option C lock-candidate - information-input combination expansion within locked taxonomy

- Status: PROPOSED / NOT LOCKED / NOT SELECTED / NOT AUTHORIZED.
- Proposed lock-candidate wording:
  - Path B may be prepared around new combinations of already-allowed
    information inputs, without adding new information-input taxonomy labels or
    reinterpreting existing labels.
  - Candidate evidence may only use information-input labels confirmed by repo
    truth and inside the locked taxonomy.
  - Any need for a new label, external data source, paid data path, Tier 4
    contact, protected-path contact, or taxonomy reinterpretation is a stop
    condition requiring separate Main/Karl resolution.
- Preservation note: locked information-input taxonomy remains unchanged. No
  external data, Tier 4, runtime, protected-path, readiness, ranking, scoring,
  or recommendation authority is introduced.
- If locked, likely downstream shape: an exact input-combination grammar
  design/lock may be required before any execution; cost is moderate and
  depends on grammar clarity.
- Modification / defer / reject triggers:
  - Modify if Main/Karl want a stricter grammar or allowed-label list.
  - Defer if locked taxonomy source must be confirmed first.
  - Reject if information-input combination work is considered taxonomy drift
    risk.
- Decision needed: LOCK / MODIFY / DEFER / REJECT.

    ranking.
- Decision needed: LOCK / MODIFY / DEFER / REJECT.

## 10. Option F lock-candidate - mixed phased Path B

- Status: PROPOSED / NOT LOCKED / NOT SELECTED / NOT AUTHORIZED.
- Proposed lock-candidate wording:
  - Path B may be prepared as a phased route: a narrow first slice followed by
    optional broader slices only after evidence and explicit Main/Karl review.
  - The first slice should use the most bounded evidence-kind expansion
    available under current taxonomy/timeframe discipline.
  - Later phases are not pre-authorized and must each preserve locked gates,
    human authority, timeframe discipline, information-input discipline,
    Phase 1 paper runtime protection, and Tier 4 boundaries.
- Preservation note: each phase separately preserves locked gates, permanent
  human gates, WP-S2c-100 criteria, D2-006/D2-007/REC-5, Phase 1 paper runtime
  protection, Tier 4/protected paths, and non-authorization boundaries.
- If locked, likely downstream shape: medium. The first slice may be low
  single-digit to low-teens WPs, with later optional tranche only after evidence
  and Main/Karl review.
- Modification / defer / reject triggers:
  - Modify if Main/Karl want a hard cap on phase count or phase size.
  - Defer if narrow first-slice definition is not yet clear.
  - Reject if phased wording risks implied automatic continuation.
- Decision needed: LOCK / MODIFY / DEFER / REJECT.
