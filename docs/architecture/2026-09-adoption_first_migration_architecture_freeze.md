This is a documentation and governance freeze. It installs, upgrades, deploys,
or migrates no framework. It changes no dependency, Python requirement,
runtime, research execution, canonical writer, scheduler, paper/live behavior,
OMS, reconciliation, hard risk, overlay, safe mode, exchange/order path, or

and economic activation requires its own later authorized package.

## Controlling principle

> Infrastructure buildability is not candidate-gated; economic activation is.

Prefect, Hermes, and Nautilus engineering/adoption proofs may therefore proceed
before genuine edge exists when a separate package authorizes bounded,
non-capital evidence using approved fixtures, synthetic data, the designated
non-winning engineering dummy, offline environments, or separately authorized
demo/testnet environments.

Still gated by genuine candidate evidence and existing human/economic controls:

- edge and candidate-performance claims;
- candidate-specific paper/shadow conclusions;
- candidate qualification or promotion;
- candidate-specific live-readiness conclusions;
- live deployment and real capital.

## Pydantic AI framing

Pydantic AI is a relatively small present implementation burden, but it is not
the future owner of a second generic reasoning/provider runtime once Hermes is
the sole generic runtime. Future work extracts and preserves deterministic CPW
research-domain logic from agent modules while retiring duplicate generic
provider/runtime ownership. Ordinary Pydantic models and JSON Schema remain
valid typed-validation tools; this decision does not retire typed validation.

## Decided CPW/Nautilus reconciliation boundary

This architecture boundary is decided; only the exact Nautilus event/API
contract remains for N2/N3 implementation proof.

position, and account reconstruction; reconnect/startup queries; missing-fill
and external-order discovery; and normal venue synchronization.

duplicate-economic-effect policy; `SAFE_MODE`, `REDUCING`, `HALTED`, or
`FROZEN` escalation; safe flatten; ambiguity handling; and any required human
reset/recovery authority.

## No-dual-authority rule

Temporary shadow comparison is permitted only when a proof package explicitly
scopes it. Permanent dual ownership is forbidden for scheduler/operational
run-state authority, canonical writer authority, trading/accounting truth,
generic agent-runtime ownership, human-approval meaning, and hard-risk
authority.

A replacement may run beside legacy code only while parity/proof is active, one
authoritative owner/writer is explicit, outputs identify their authority, and
the deletion/disable trigger is recorded. No migration package may leave two
active authoritative writers indefinitely.

## Compatibility shims and boundary adapters

Allowed temporary examples include a lab-state/read projection and a research-
agent import facade needed for consumer migration. Every temporary shim must
record its owner, reason, consumers, non-authority statement, and deletion
trigger.

Potentially permanent narrow adapters are a CPW-to-Nautilus result normalizer
needed to preserve Result Population semantics and a read-only legacy canonical
decoder needed for historical readability. These are boundary translators, not
second owners of orchestration, trading truth, approval, or canonical authority.

## Retirement criteria

A subsystem is not retired because a replacement merely exists. A later
explicit retirement package may decommission it only after all applicable
conditions hold:

1. replacement proof passed;
2. consumers migrated;
3. old writer/runtime disabled;
4. historical evidence remains readable;
5. no active imports or consumers remain;
6. replacement tests cover required behavior;
7. clean-environment and required broad validation show no hidden dependency;
8. required rollback/transition evidence is complete; and
9. no authority remains silently shared.

CPW-MIG-00 deletes and disables nothing.

## Storage-class freeze

### Canonical

Repo-controlled, versioned authoritative project/scientific truth, including
applicable Strategy Specs, Variant Manifests, Sweep Plans, Result Populations,
candidate lifecycle/decision records, material human approvals, canonical
crossing receipts, and required provenance. Persistence follows explicit CPW
canonical authority.

### Active / provisional

Noncanonical work in progress in a gitignored active workspace and/or future
Prefect result/artifact storage. It is explicitly non-authoritative and is
reproducible from frozen inputs where the relevant contract requires it. MIG-01
or later Prefect work decides the physical backend.

### Ephemeral

Disposable task-local files, caches, transient logs, and intermediate
transforms. Presence creates no authority.

### Operational history

Prefect run/task history, CI/run logs, retry/recovery records, and operational
receipts. Operational history is not automatically canonical scientific
evidence.

### Historical accepted proof

Compact retained/archive evidence from accepted legacy packages: material
proof, accepted receipts, and compatibility fixtures/readers. It remains
readable but does not remain the active working store merely because it is
historical. Tracked package scratch is not the permanent active-workspace model.
