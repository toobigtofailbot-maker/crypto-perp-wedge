# WP-LABPROD-COCKPIT-PIPELINE-STATE-02 — Cockpit pipeline run-state panel

Status: READY_FOR_REVIEW

## Scope

Extend the merged static lab product cockpit (`tools/lab_cockpit`) with a
read-only **pipeline run-state** panel so Karl can visually inspect lab-pipeline
run state, approval needs, blockers, and per-run artifacts — with no run,
approve, promote, retry, candidate, or scheduler control. Additive only; existing
cockpit panels and tests are unchanged.

## Result

- `tools/lab_cockpit/model.py` — additive `build_pipeline_state(...)` projection
  over committed `tools/lab_pipeline` run packets, with per-run status mapping,
  spine-only detection, and fail-closed handling; new pipeline non-authority
  flags; wired into `build_cockpit_data`.
- `tools/lab_cockpit/render.py` — additive pipeline run-state HTML section
  (KPI strip, run cards, stage timeline, approval/blocked/spine callouts,
  artifact drilldown) and a matching markdown section; new CSS only.
- `tests/test_lab_cockpit_pipeline_state.py` — 21 focused tests, including a
  contract test that drives the **real** orchestrator into a temp dir and
  projects it.
- `docs/research/LAB_PRODUCT_COCKPIT_PIPELINE_STATE.md` — surface doc.
- `scratch/WP-LABPROD-COCKPIT-PIPELINE-STATE-02/**` — discovery, contract,
  reproducible fixture generator, committed sanitized run fixtures, render
  fixtures, non-authority audit, validation summary.

## Visual panels delivered

Pipeline runs · run-state: KPI strip (runs / awaiting approval / blocked-invalid
/ complete-spine-only / complete-real); honest spine-only banner; per-run cards
with status chip, run metadata, current stage, full stage timeline, an
awaiting-approval callout (scope + preregistration packet sha256), a
blocked-reason callout, a `runner_invoked=false` spine-proof callout, and a
present/missing + sha256 artifact drilldown. Unavailable and malformed states
render explicit fail-closed cards.

## Exact data sources consumed

Committed run packets under
`scratch/WP-LABPROD-COCKPIT-PIPELINE-STATE-02/pipeline_runs/<run_id>/`:
`pipeline_state.json`, `noncanonical_execution_summary.json`,
`approval_requirement.json`, `artifact_index.json` (sha by basename, display
only), plus `pipeline_trace.json`, `operator_review_packet.md`,
`non_authority_assertions.json`, `preregistration_packet.json`,
`pipeline_request.json` in the drilldown. Fixtures were generated by the real
orchestrator, then path-sanitized to repo-relative with `artifact_index` hashes
recomputed (honest for committed bytes).

## No-control / static guarantee

Rendered HTML contains no `<script>`, `<button>`, `<form>`, `<input>`, `onclick`,
`fetch(`, `setInterval`, `setTimeout`, meta refresh, or external network
reference (asserted by tests and `non_authority_audit.json`). No absolute/secret
paths leak into the surface. Output is byte-deterministic for the same checkout
and fixtures.
