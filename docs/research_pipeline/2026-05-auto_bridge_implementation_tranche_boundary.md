## C. Design Problem

the design tranche, but implementation remains unauthorized.

schema, validator, query, artifact-emission, candidate-binding, runtime, or
approval authority.

design-tranche checkpoint can present a clean decision surface to

## D. Implementation-Tranche Boundary

Future implementation may be considered only after explicit authorization for
a specific tranche. The following categories could potentially be included in a
future tranche, but none are authorized here.

1. Bridge intake specification
   - source discovery;
   - source identity;
   - allowed source paths;
   - non-canonical intake boundary;
   - rejection of pre-bridge AUTO outputs for canonical transformation.

2. Provenance capture implementation
   - source identity capture;
   - run context capture;
   - code/config identity capture;
   - transformation trace;
   - review trace;
   - only if separately authorized.

3. Transformation / normalization implementation
   - mapping from future post-bridge AUTO outputs to an authorized target
     structure;
   - deterministic transformation rules;
   - failure and exclusion behavior;
   - no silent fallback.

4. Artifact or intake-record emission
   - only after explicit artifact-family or non-canonical intake-record
     authority;
   - no REP/OL/REC/EXP/lifecycle/registry/query emission without separate
     explicit authority.

5. Validator and schema work
   - only after explicit schema/validator package authority;
   - no validator bypass;
   - rejection of missing provenance and pre-bridge outputs.

6. Query or review surface
   - only after explicit query/review-surface authority;
   - query exposure remains read-only and downstream of artifact authority;
   - query layer must not create evidence.

7. Reporting / report-back surface
   - created/rejected/skipped summary;
   - validation results;
   - boundary and authority report-back.

All categories are possible future work only. They are not current
authorization.
