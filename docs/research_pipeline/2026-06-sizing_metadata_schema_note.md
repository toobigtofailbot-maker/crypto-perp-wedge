# Sizing Metadata Schema Note

## Status / authority boundary

`WP-REALISM-SIZING-02d` adds optional structured sizing metadata to the
result-population schema and validator. The metadata is for future result
populations that record sizing method explicitly.

This package does not write a canonical result population, mutate existing
result populations, edit runner or lib code, register candidates, rank
variants, mark readiness, promote strategies, or authorize paper/live/runtime
behavior.

## Structured sizing fields

The schema adds optional top-level `sizing_metadata` with these fields:

- `sizing_mode`
- `target_leverage`
- `sizing_equity_basis`
- `entry_reference_price_basis`
- `max_leverage_cap`

Closed sizing modes:

- `fixed_order_size`
- `dynamic_equity_target_leverage`

Closed basis strings currently include:

- `not_applicable_fixed_order_size`
- `realized_available_equity_at_entry`
- `next_bar_open_pre_fee_slippage`

For `fixed_order_size`, `target_leverage` may be absent. If present, it must be
finite and positive. Fixed-mode basis fields use
`not_applicable_fixed_order_size`.

For `dynamic_equity_target_leverage`, `target_leverage`,
`sizing_equity_basis`, and `entry_reference_price_basis` are required. Target
leverage must be finite and positive.

If `max_leverage_cap` is present, it must be finite and positive.

## Identity-bearing posture

`sizing_metadata` is identity-bearing for future result populations that include
it. The schema permits `sizing_metadata` in both:

- `input_identity_hash.hash_scope`
- `result_population_identity_hash.hash_scope`

The validator requires both identity hash scopes to include
`sizing_metadata` whenever the top-level `sizing_metadata` object is present.
Changing `sizing_mode`, `target_leverage`, basis fields, or leverage cap
therefore changes the relevant computed identity hash when those fields are
included.

This aligns with the `WP-REALISM-SIZING-02c` observation that
`backtest_assumption_summary` is already identity-scoped. Structured metadata
removes ambiguity between text-only sizing provenance and explicit sizing
fields.

## Prior RP compatibility

Existing committed result populations remain immutable and valid without
backfill:

- `RP-2134`
- `RP-4492`
- `RP-6688`

Old result populations may omit `sizing_metadata` and may omit
`sizing_metadata` from identity hash scopes. They remain valid under their
recorded assumption text and recorded pipeline version.

No existing result population is rehashed, renamed, amended, or regenerated by
this package.

## Pipeline-versioning implications

Future dynamic-sizing canonical result populations must include structured
sizing metadata and include that metadata in identity-hash scope.

Post-02b/02c fixed-mode reruns may differ in identity if sizing parameters are
reflected in identity-scoped assumption text or in structured sizing metadata.
That is a pipeline-versioning fact, not a committed-RP integrity issue.

Canonical reruns remain Karl-gated. This package prepares the schema and
validator contract only.

## Validator behavior

The result-population validator now:

- accepts old result populations with no `sizing_metadata`;
- validates `sizing_metadata` when present;
- rejects unknown `sizing_mode` values;
- rejects missing dynamic sizing fields;
- rejects zero, negative, non-number, NaN, or infinite `target_leverage`;
- rejects unsupported basis strings;
- rejects zero, negative, non-number, NaN, or infinite `max_leverage_cap`;
- requires `sizing_metadata` in both identity hash scopes when present;
- preserves existing validation behavior for other result-population fields.

## Tests and validation
