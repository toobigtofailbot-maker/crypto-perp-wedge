DEFECT FOUND AND FIXED
----------------------
Console emitted, once per chart:
  [ECharts] Specified `grid.containLabel` but no `use(LegacyGridContainLabel)`;
            use `grid.outerBounds` instead.
ECharts 6 IGNORES `grid.containLabel` unless the legacy feature is registered. Because of
that, `grid.top: 16` reserved no room for a y-axis `name`, and the axis names "variants"
(both histograms) and "return" (scatter) were CLIPPED at the canvas top edge.

Smallest chart-rendering fix, confined to operator_dashboard_frontend:
  - lib/chartTheme.ts: drop the ignored `containLabel` (provably a no-op -- ECharts says so
    and ignores it, so removal cannot change layout) and add GRID_TOP_WITH_AXIS_NAME = 32.
  - MetricHistogramChart.tsx / DrawdownVsReturnScatter.tsx: use that top margin, since
    these are the only charts that name a y-axis.

Re-verified after the fix: axis names fully visible; the ECharts console message is gone
(fresh 4-chart load emits nothing); horizontal bar charts (queue, funnel, registry) show
no label clipping, confirming the `containLabel` removal was a true no-op; tooltips and
legend still behave; typecheck / lint / build still pass.
