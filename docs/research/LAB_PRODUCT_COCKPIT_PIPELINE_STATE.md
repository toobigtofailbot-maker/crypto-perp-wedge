# Lab Product Cockpit — Pipeline Run-State Panel (read-only)

This document describes the read-only pipeline run-state panel added to the
static lab product cockpit (`tools/lab_cockpit`). It extends the merged static
cockpit (see `LAB_PRODUCT_COCKPIT_SURFACE.md`) so an operator can visually
inspect lab-pipeline run state, approval needs, blockers, and per-run artifacts
without leaving the static page — and without any run/approve/promote control.

## What it shows

A new **Pipeline runs · run-state** section, rendered directly after the lab
overview:

- **KPI strip** — total runs, awaiting-approval count, blocked/invalid count,
  complete-spine-only count, and complete-real-runner count.
- **Honest-labeling banner** — while no run has invoked a real runner, the panel
  shows: *"State spine / prereg approval contract only; real agent/runner adapter
  flow not yet complete."*
- **Run cards** — one per committed run packet, each with:
  - a status chip (awaiting prereg approval / blocked / complete · spine only /
    complete / unavailable);
  - the source idea and run metadata (symbol, timeframe, requester, request id);
  - the current stage and a **stage timeline** of all pipeline stages colored by
    status;
  - an **approval-needed callout** (scope + preregistration packet sha256) when
    the run is halted awaiting approval;
  - a **blocked-reason callout** listing the blocker(s);
  - a **spine-proof callout** stating `runner_invoked=false` honestly;
  - an **artifact drilldown** table (file, present/missing, sha256).

The markdown renderer carries the same information as a table for diff-friendly
review.

## Data sources consumed

The panel is a pure projection of committed `tools/lab_pipeline` run packets
under `scratch/WP-LABPROD-COCKPIT-PIPELINE-STATE-02/pipeline_runs/<run_id>/`:

- `pipeline_state.json` — status, current stage, stage records, blocked reasons;
- `noncanonical_execution_summary.json` — `runner_invoked`, `execution_kind`;
- `approval_requirement.json` — approval scope + preregistration packet hash;
- `artifact_index.json` — per-file sha256 (display only, by basename);
- `pipeline_trace.json`, `operator_review_packet.md`,
  `non_authority_assertions.json`, `preregistration_packet.json`,
  `pipeline_request.json` — surfaced in the artifact drilldown.

No pipeline runs are committed on `origin/main` (the orchestrator writes to a
gitignored `outputs/` root), so this package commits a small honest fixture set
generated by the **real** orchestrator. See
`scratch/WP-LABPROD-COCKPIT-PIPELINE-STATE-02/generate_pipeline_run_fixtures.py`.

## Fail-closed behavior

- Runs directory absent/empty → the panel is `unavailable` (never fabricated).
- A run with a missing/malformed `pipeline_state.json` → an explicit invalid run
  card (`blocked_or_invalid`), not a synthesized run.

## Honest labeling

The approved run is a deterministic **state-spine proof** with
`runner_invoked=false`; it is labeled as spine-only and is never presented as a
real completed hypothesis run. Real agent/runner adapters are a later package
(`WP-LABPROD-PIPELINE-AGENT-ADAPTERS-02`); until then `complete (real runner)`
stays zero. When a later package emits an adapter gap register, a structured
per-run gap row can be added read-only.

## No-control / static guarantee

The rendered HTML contains no `<script>`, `<button>`, `<form>`, `<input>`,
`onclick`, `fetch(`, `setInterval`, `setTimeout`, meta refresh, or external
network reference. There is no run, approve, retry, promote, candidate, or
scheduler control. Output is byte-deterministic for the same checkout and
fixtures.

## Non-authority

Read-only visualization only. This surface grants no run, approval, candidate,
crossing, promotion/readiness, paper/live/runtime, scheduler/autonomy,
notification, provider/API, credential, dependency/config, data-acquisition, or
protected-path authority. Any real transition or approval requires separate,
explicit human action out-of-band; this cockpit cannot grant it.
